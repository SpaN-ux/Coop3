# CoopVC

Co-op for **GTA Vice City**, on the networking, server, launcher and installer
of CoopIII (MIT, see `LICENSE`). This is a Vice City project: it has no GTA III
target, and none of CoopIII's game-engine code came with it, because every
address and struct in that code belonged to another executable.

**State: milestone 3a of 6. It is not playable yet.** The client loads, checks
that the game is the supported executable, waits for the game to start up,
hooks the once-a-frame call, and from it reads the player, the pools and the
clock into the log. It only reads. Nothing is sent over the network and nothing
in the world is touched.
`docs/porting.md` has the plan and what is proven.

## The one supported executable

CoopVC's addresses belong to one exact `gta-vc.exe`:

    size  3 088 896 bytes
    MD5   167A5C8B31B3E0DBEFA033CA24453D4E
    PE timestamp 2012-09-10

Anything else is refused at load time. This is deliberate: a hook at the wrong
address does not fail cleanly, it corrupts some other function and the game
dies minutes later. The exe is not called "1.0" or "1.1" here because that was
never established from the file itself.

`python tools/vcexe/check.py <path to gta-vc.exe>` proves every address in
`client/src/game/addresses.h` against the file, without running it.

## What is in the tree

| Path | What |
|---|---|
| `client/` | `CoopVC.asi`, the part that goes into the game. Small, and growing. |
| `sdk/` | The wire protocol and ENet transport. Inherited, see below. |
| `server/` | The session server (window and `--nogui`). |
| `launcher/`, `installer/`, `ui/` | Starts the game with the co-op marker; one-file Setup; shared look. |
| `tools/` | The test programs, and `vcexe/check.py`. |

## Inherited from CoopIII, and what that means

The protocol (`sdk/include/coopvc/protocol.h`, `docs/protocol.md`) and the
server code still carry the history of the game they were written for: their
comments describe GTA III behaviour, and some message groups (cranes, the lift
bridge, gates, rampage votes) exist only because III has those things. They are
dormant: nothing in the client sends them. They stay until Vice City has its
own equivalent or a decision is made to drop them, and a comment that describes
III's engine has **not** been checked against Vice City's.

The protocol version is `10097`, so a CoopIII client or server can never join a
CoopVC session.

## Building

xmake, MSVC, static CRT, 32-bit: `xmake f -a x86 && xmake build`. The test
programs are `set_default(false)`: `xmake build <name> && xmake run <name>`.
The same sources also cross-compile with `i686-w64-mingw32` (that is how the
tests here were run, under Wine, with `-msse2 -mfpmath=sse`: without SSE math
a few float comparisons differ from MSVC's).

## What has been verified, and how

Not everything has had the same scrutiny. Plainly:

| Part | Verified |
|---|---|
| `CoopVC.asi` (client) | Compiles and links (MinGW, 32-bit). Startup paths run under Wine in a process that is not Vice City. **Not run inside the game.** |
| `client/src/game/addresses.h` | 89 byte-level assertions against the exe (`tools/vcexe/check.py`), plus a deliberate-break check that the script fails when an address is wrong. |
| Frame hook, world reading | `frametest` (26 checks, real detour) and `worldtest` (35 checks, fake world), run under Wine. |
| Server, session, config, network | `sessiontest` (1385), `servertest` (278, real sockets), `configtest`, `interptest`, `patterntest`, `launchertest`, `basetest`: pass under Wine with SSE math. |
| Launcher, server and installer windows, the UI library | **Compile** with MinGW against Dear ImGui 1.92.1. Never run: no GPU or desktop here. |
| `server/probe.cpp`, the installer payload step | Not compiled here: the first needs the Windows SDK's `natupnp.h`, the second is generated by xmake. |
| The MSVC / xmake build | Never run. Everything above was built with MinGW. |
